## 0. 五原则的操作化定义

| # | 原则 | 操作化（怎么算遵守） | 违反的样子 |
|---|------|---------------------|-----------|
| 一 | **反馈强度与事件重要性成正比** | 每个事件先定级（T0-T3，见 §1），同级别事件共享同一"反馈 bundle"强度；跨级不越权（T1 不许用震屏/顿帧） | 按键滴答带全屏白闪；Boss 之死只有一行 log |
| 二 | **每约 3 秒至少一个反馈** | 回合制的适配：**操作爆发期**（按键→动画链）有连续帧级反馈；**思考期**（玩家读盘算账）由 T0 环境反馈（呼吸/闪烁/BGM）托底 | 玩家盯着静止画面算 10 秒伤害 |
| 三 | **同一事件 ≥2 个通道** | 每个事件在 通道矩阵（§3）里至少两格打勾；视觉+听觉为标配组合（本项目无触觉通道） | 敌人打了我只有一行流水文字 |
| 四 | **缓动与二级动作制造活物感** | 位移/缩放/淡入一律走缓动（禁线性）；主要实体带 ≥1 个待机二级动作；大动作带残影/跟随物 | 元素瞬移出现；画面像幻灯片 |
| 五 | **Juice 是可调参数，不是一次性美术活** | 所有效果的帧数/强度/开关集中在 `JUICE` 配置（§6），改参数不改逻辑；验收断言按参数生成 | 动画帧数散落硬编码在各场景里 |

**与本地 skill 的关系**：`game-feel` skill 是引擎无关的通用技法库（trauma 震屏、hit-stop、squash&stretch、分层 bundle），其"importance tiers / feedback bundle"模式即原则一/三/五的通用表述；本文档是它在 pyxel 约束 + 本项目架构下的落地。

## 1. 事件重要性分级（Tier）

| Tier | 定义 | 本项目事件 |
|------|------|-----------|
| **T3 关键** | 全局性后果、改变游戏阶段 | 开局确认；进入战斗；战斗胜利；战斗失败；逃离成功；燃料耗尽 |
| **T2 重要** | 局部但玩家在意 | 跳迁下达/落地；踩升级点；技能施放；火炮命中；**敌人攻击我**；敌人被击杀；引擎故障发生；故障跳过；升级应用 |
| **T1 常规** | 高频小操作 | 引擎/目标/选项光标移动；种子数字输入；回合开始掷出力；子系统分配（未命中差异） |
| **T0 环境** | 无事件时的待机层 | 飞船光环呼吸；选中圈闪烁；引擎图像白点呼吸；BGM |

**强度对应**（bundle 预设，来自 skill 的 tier 模式）：
- T1 = 单通道轻反馈（滴答音 / 行高亮）
- T2 = 双通道中反馈（音效 + 顿帧/白闪/横幅，约 0.1~0.5s）
- T3 = 双通道以上强反馈（转场 + 音效 + 压暗/白闪，0.5~1.5s，可叠加）

## 2. 本项目可用反馈通道工具箱（pyxel 约束下）

| 通道 | 手段 | 备注 |
|------|------|------|
| 视觉·闪白/闪色 | `pyxel.pal(原色,白)` 重映射精灵后绘制，2-3 帧 | 无 alpha，pal 是最便宜的"整体变色" |
| 视觉·震屏 | `pyxel.camera(x,y)`，**trauma² 衰减 + sin 驱动**（skill 模式，勿每帧随机） | 幅度 1-3px、≤10 帧 |
| 视觉·顿帧 | 场景帧计数冻结 update（现 FREEZE_F 模式） | pyxel 无 timescale，帧计数即等效；敌人逻辑推迟 |
| 视觉·粒子 | 逐帧 `circ/rect` 列表（出生-速度-衰减） | 击破爆散、落地尘 |
| 视觉·伤害数字 | 数值文本上飘 + 色阶渐隐（二级动作） | 数据现成（assign 的 dmg） |
| 视觉·残影 | `pyxel.pal(7,暗色)` 重画历史位置（已实现） | |
| 视觉·抖动渐变 | `pyxel.dither(p)`（已实现：转场/红闪/压暗） | |
| 视觉·squash | 白盒：改绘制半径/矩形尺寸；资产版：精灵无缩放 → 用偏移+闪色替代 | pyxel 无图像缩放 |
| 听觉·音效 | pyxres 槽位（已用 0-7、12；**8-11 是 BGM 乐句**，新音效从 13 起） | 资产版才有声；白盒静音（两版架构） |
| 听觉·BGM | 音乐 0 循环 | 可按场景切乐句（暂未做） |

**明确没有的通道**：shader、时间缩放、手柄震动、音频混音/闪避。设计时不得依赖。

## 3. 现状审计：事件 × 通道矩阵（2026-10-23 基线）

> **2026-10-24 第二轮接入后状态**：阶段一~四已全部实施——敌人回合过程化（react 10 帧：本舰白纱闪+trauma 震屏+红色伤害数字）、火炮命中数字（橙）、击杀粒子爆散（10 粒）、敌行受击白闪、胜利横幅 ease-out-back 弹入；音效 13-18 补齐 + **故障警报前移至判定瞬间**（fault 事件）；兴趣点悬浮（按类型分相位）/跳迁后坐/落地尘；**分场景 BGM**（音乐 0-3=菜单/地图/战斗/结算，`play_bgm` 钩子随 change_scene 切换）；参数全部收进 `JUICE` 字典（含 `enabled/reduce_flash/reduce_shake`）。下表为接入前基线，保留作对照；审计达标线见 §8。

✓=已有 · ✗=缺失 ·（✗）=有实现但强度/时机不达原则

| 事件 | Tier | 视觉 | 听觉 | 判定与缺口 |
|------|------|------|------|-----------|
| 光标移动（菜单/地图/升级） | T1 | ✓ 行高亮+▶/闪烁圈 | ✓ 光标音 | **达标** |
| 种子数字输入/退格 | T1 | ✓ 字符出现 | ✗ | 缺滴答音 |
| 回车开局 | T3 | ✓ fade 转场 | ✗ | 缺确认音（T3 只有一通道，违反原则三） |
| 跳迁下达→飞行 | T2 | ✓ ease-out+两级残影 | ✗ | 缺引擎/起跳音 |
| 落地（摄像机跟随） | T2 | ✓ 平滑跟随 | ✗ | 缺落地音/尘粒 |
| 落普通星球 | T1 | ✗（回到待命） | ✗ | 反馈空窗（见 §4） |
| 踩升级点 | T2 | ✓ fade | ✗ | 缺"发现"音 |
| 踩敌人→进战斗 | T3 | ✓ 白闪×2+光圈 | ✗ | 缺战斗警报音 |

| **引擎故障发生** | T2 | ✓ 灰行【故障】+图像点入故障区 | ✗ | **音效 12 只在"跳过"时播，判定瞬间不响——时机错位** |
| 技能施放 | T2 | ✓ 16px 横幅+残影 | ✓ 能量音 | **达标（范例）** |
| 火炮命中 | T2 | ✓ 顿帧+敌行高亮 | ✓ 火炮音 | 缺敌受击白闪、伤害数字 |
| 敌人被击杀 | T2/T3 | （✗）直接跳胜负横幅 | ✓ 击破音 | 缺 2-3 帧粒子爆散 |
| 分配护盾/能量 | T2 | ✓ 顿帧+行高亮 | ✓ 对应音 | **达标** |
| **敌人攻击我** | T2 | **✗**（只有流水文字） | ✓ 受击音 | **原则三最大违反：视觉通道缺失** |
| 故障跳过 | T2 | ✓ 红闪 0.5s | ✓ 警报音 | **达标** |
| 战斗胜利/失败 | T3 | ✓ 压暗+横幅 | ✓ 胜/败音 | 缺横幅 overshoot 弹入 |
| 离开战斗 | T2 | ✓ iris | ✗ | 可接受（紧随 T3 音效） |
| 升级应用 | T2 | ✓ fade 回地图 | ✗ | 缺获得音+浮字 |
| 逃离成功/燃料耗尽 | T3 | ✓ 结算画面 | ✗ | 缺结算音（胜利/失败变奏） |
| 待机（全场景） | T0 | ✓ 呼吸光环/闪烁圈/白点呼吸 | ✓ BGM | 缺兴趣点悬浮（effects_lab 页4 已调研） |

**矩阵结论**：视觉通道覆盖良好；**听觉通道是系统性短板**（T2/T3 中 8 个事件缺音）；两个原则三违反点（敌人攻击、开局确认）+ 一个时机错位（故障警报）。

## 4. "每 3 秒一个反馈"节奏分析

回合制游戏的节奏 = **操作爆发期**（玩家按键触发的动画链）与**思考期**（读数值、算路线）交替：

| 阶段 | 时长 | 反馈现状 | 判定 |
|------|------|---------|------|
| 地图跳迁链 | 0.9s（飞行 0.4s+镜头 0.5s） | 残影每帧可见 → 秒级密度极高 | ✓ |
| 战斗分配链 | 0.17s 顿帧 → **敌人回合 ≈1 帧完成** → 新回合 | 分配有顿帧+音效；**敌人反击在单帧内结束，视觉上不可感知** | ✗ 断裂点 |
| 升级流程 | fade 进(0.5s) → 选单操作 → fade 出 | 每次按键有反馈；fade 期间有连续动画 | ✓ |
| 思考期（地图选点） | 玩家决定，可达 10s+ | 光环呼吸+选中圈闪烁+BGM（T0 托底） | ✓（悬浮接入后更稳） |
| 菜单输种子 | 每次按键 | 字符出现，无声 | （✗）轻空窗 |
| 结算画面 | 玩家停留 | 静态文字 | ✗（可接受，但加音效更好） |

**修复优先**：敌人回合过程化（顿帧或 3-5 帧受击表现把"瞬间"拉长到可感知），是全游戏反馈节奏最大的断裂点。

## 5. 活物感清单（原则四）

**已有**：
- 缓动：ease_out_cubic（跳迁飞行、摄像机跟随）、dither 渐变（全部转场/红闪/压暗）、三角波（红闪强度）
- 二级动作：跳迁两级残影、技能横幅残影、飞船呼吸光环、选中圈闪烁、引擎图像白点呼吸

**候选（按收益排序）**：
1. 敌人受击白闪 + squash（白盒：三角缩 1 帧 → 弹回）
2. 伤害数字上飘渐隐（每次火炮命中，数据现成）
3. 兴趣点悬浮 `y += sin(t+相位)`（按类型分相位；effects_lab 页4 代码现成）
4. 跳迁 anticipation：起跳前 2 帧反向后坐（T2 强度不越权，仅位移 1px）
5. 胜利横幅 ease-out-back 弹入（overshoot）

## 6. 可调参数架构：`JUICE` 配置（原则五落地提案）

**现状**：帧参数已集中（`TRANS_* / JUMP_* / FREEZE_F / RED_F / BANNER_F` 常量区）——原则五的雏形已有，但缺**强度维度、全局开关、级别缩放**。

**提案**：白盒版常量区收敛为单一配置字典（两版共享，与资产层无关，不破坏双版不变式）：

```python
JUICE = {
    "enabled": True,            # 总开关（一键关全部 juice，用于对比/无障碍）
    "reduce_flash": False,      # 无障碍：削减闪白/红闪强度（skill pitfall 建议）
    "reduce_shake": False,      # 无障碍：削减震屏幅度
    "trans":  {"fade_f": 7, "iris_f": 10, "flash_f": 8},
    "jump":   {"ship_f": 12, "cam_f": 15, "ghost_lags": (4, 8)},
    "fight":  {"freeze_f": 5, "red_f": 15, "banner_f": 32,
               "hit_flash_f": 3, "shake_px": 2, "shake_f": 8},
    "tier_scale": {"1": 0.6, "2": 1.0, "3": 1.4},   # 强度乘子：帧数×scale
}
```

- **迁移路径**：现有常量逐个改为 `JUICE["fight"]["freeze_f"]` 读取（机械替换，72 用例与 MCP 断言不受影响）；新效果一律先入配置再实现。
- **验收联动**：MCP 取证按 `JUICE` 参数化（改参数→重跑同一像素断言），证明"可调"不是口号。
- **强度实现约定**：帧数类参数 × `tier_scale`；幅度类参数（震屏 px、闪白覆盖）× `reduce_*` 折减系数。

## 7. 落地优先级（建议，未实施）

| 序 | 改动 | 修复的违反 | 规模 |
|----|------|-----------|------|
| 1 | **敌人回合过程化**：我方受击白闪 2-3 帧 + trauma 震屏 + 伤害数字上飘；击杀加 3 帧粒子爆散 | 原则三（最大违反）+ 原则二（断裂点） | 中 |
| 2 | **音效补齐**（资产版，make_assets 扩槽 13+）：输入滴答/开局确认/跳迁引擎/落地/升级获得/战斗警报/结算变奏 | 原则三（8 个事件） | 中（每音效一行表） |
| 3 | **故障警报时机修正**：音效 12 从"跳过时"提前到"故障判定时"（begin_turn） | 原则一时机 | 小 |

**注意**：UI 重设计落定后，涉及 UI 布局的效果（伤害数字起点、横幅 Y）应引用编辑器导出的坐标，不要二次硬编码。

## 8. 验收方法

- 每项改动：pyxel-mcp 定帧截图 + 像素断言（参考 `runs/fx_*.png` 断言风格：白闪覆盖率、震屏像素位移、红闪峰值、粒子计数）。
- 节奏审计：用 MCP 输入时间表复算反馈间隔，验证"任意 3s 窗口内 ≥1 个反馈"（含 T0）。
- 通道审计：改动后更新 §3 矩阵，✗ 清零为达标线。
